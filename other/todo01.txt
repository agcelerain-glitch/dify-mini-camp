■ 各サービスの役割（超わかりやすく）
================================================================

  GitHub    → コードの保管庫。VercelやCollaboratorと共有するための場所
  Vercel    → Webサイトを世界に公開する場所（GitHubと自動連携）
  Supabase  → データベース＋ログイン機能がセットのサービス
              「ユーザーの学習進捗を保存」「Googleログイン」を担当
  Dify      → AIチャットボットをブロックで組み立てる場所
              プログラムを書かずにAIの処理フローを作れる

  ■ データの流れ（全体像）

    ユーザー
      ↓ ブラウザでアクセス
    Vercel（Next.jsアプリ）
      ↓ ログイン認証      ↓ AI会話・採点
    Supabase             Dify API
    (DB/Auth)            (AIメンター)
      ↓
    学習進捗を保存

■ STEP 2：Supabase のセットアップ
================================================================

  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  Supabase とは？
  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  Supabaseは「データベース＋ログイン機能」を無料で提供するサービスです。

  通常、Webアプリ開発では：
  - データベースサーバーを自分で用意する
  - Googleログイン機能を自分でコーディングする
  …が必要ですが、Supabase はこれをすべて代わりにやってくれます。

  今回使う機能:
  - Authentication: Googleログインを設定するだけで使える
  - Database: PostgreSQL（本格的なDB）がすぐ使える
  - Row Level Security: 「自分のデータしか見えない」を自動設定

  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  [ ] https://supabase.com/dashboard にログイン

  [ ] 左サイドバーの「Settings」（歯車アイコン）→「API」をクリック

  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  2-2. データベーステーブルの作成
  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  [ ] Supabaseダッシュボードで「SQL Editor」を開く（左サイドバー）
  [ ] 「New query」ボタンをクリック
  [ ] 以下のSQLを貼り付けて「Run」ボタンをクリック:

      --- ここから貼り付け ---
      -- ユーザーテーブル（Supabaseのauth.usersを参照する設計）
      CREATE TABLE public.users (
        id UUID REFERENCES auth.users(id) PRIMARY KEY,
        username TEXT,
        display_name TEXT,
        avatar_url TEXT,
        created_at TIMESTAMPTZ DEFAULT NOW()
      );
      ALTER TABLE public.users ENABLE ROW LEVEL SECURITY;
      CREATE POLICY "Users can view own profile"
        ON public.users FOR SELECT USING (auth.uid() = id);
      CREATE POLICY "Users can update own profile"
        ON public.users FOR UPDATE USING (auth.uid() = id);
      CREATE POLICY "Users can insert own profile"
        ON public.users FOR INSERT WITH CHECK (auth.uid() = id);
      --- ここまで ---

  [ ] 「New query」をもう一度クリック
  [ ] 以下のSQLを貼り付けて「Run」:

      --- ここから貼り付け ---
      -- 学習進捗テーブル
      CREATE TABLE public.progress (
        id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
        user_id UUID REFERENCES public.users(id) ON DELETE CASCADE,
        current_phase INTEGER DEFAULT 1 CHECK (current_phase BETWEEN 1 AND 5),
        phase1_cleared_at TIMESTAMPTZ,
        phase2_cleared_at TIMESTAMPTZ,
        phase3_cleared_at TIMESTAMPTZ,
        phase4_cleared_at TIMESTAMPTZ,
        phase5_cleared_at TIMESTAMPTZ,
        updated_at TIMESTAMPTZ DEFAULT NOW()
      );
      ALTER TABLE public.progress ENABLE ROW LEVEL SECURITY;
      CREATE POLICY "Users can view own progress"
        ON public.progress FOR SELECT USING (auth.uid() = user_id);
      CREATE POLICY "Users can update own progress"
        ON public.progress FOR UPDATE USING (auth.uid() = user_id);
      CREATE POLICY "Users can insert own progress"
        ON public.progress FOR INSERT WITH CHECK (auth.uid() = user_id);
      --- ここまで ---

  [ ] 「Table Editor」（左サイドバー）で users と progress テーブルが
      作成されていることを確認

■ STEP 3：Dify ワークフローの構築（最重要・最難関）
================================================================

  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  Dify とは？（基本概念）
  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  Difyは「ブロックをつなぐだけでAIアプリが作れる」サービスです。
  プログラムを書かなくてもAIの処理フローが設計できます。

  使うブロックの説明:
  ┌────────────────────────────────────────────────┐
  │ ブロック名      │ 役割                              │
  ├────────────────────────────────────────────────┤
  │ 開始 (Start)   │ ワークフローの入口。変数をここで定義  │
  │ 質問分類器      │ ユーザーの入力を複数カテゴリに分類  │
  │ IF/ELSE       │ 条件によって処理を分岐             │
  │ LLM           │ AIに文章を生成させる本体           │
  │ テンプレート    │ 複数の変数を組み合わせてテキストを作る│
  │ 変数集約器      │ 複数ルートの結果を1つにまとめる     │
  │ 回答 (Answer)  │ ユーザーへの最終的な返答           │
  └────────────────────────────────────────────────┘

  今回作るフローのイメージ:
  開始 → 質問分類器 ─→ [質問・雑談ルート] → LLM(メンター) → 変数集約器 → 回答
                    └→ [課題提出ルート]  → LLM(採点)    ↗

  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  3-1. Difyでワークフローアプリを作成
  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  [ ] https://cloud.dify.ai にログイン
  [ ] 上部の「スタジオ」または「Studio」をクリック
  [ ] 「新しいアプリを作成」または「Create App」
  [ ] アプリの種類: 「ワークフロー（Workflow）」を選択
      ※「チャットボット」ではなく「ワークフロー」を選んでください
  [ ] 名前: 「Dify mini Camp メンター v1」
  [ ] 「作成」をクリック → ワークフロー編集画面が開く

  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  3-2. 開始ブロックの設定
  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  [ ] 画面中央に「開始」ブロックが表示されている
  [ ] 「開始」ブロックをクリックして右側の設定パネルを開く
  [ ] 「入力フィールドを追加」を4回クリックして以下を設定:

      ─── 変数1 ───
      フィールド名（変数名）: sys_query
      種類（タイプ）: テキスト（Short text）
      ラベル: ユーザーの入力
      必須: オン（チェック）

      ─── 変数2 ───
      フィールド名（変数名）: current_phase
      種類（タイプ）: テキスト（Short text）
      ラベル: 現在のフェーズ番号
      デフォルト値: 1
      必須: オン（チェック）

      ─── 変数3 ───
      フィールド名（変数名）: interaction_type
      種類（タイプ）: テキスト（Short text）
      ラベル: インタラクション種別
      デフォルト値: question
      必須: オン（チェック）
      説明: "question"=質問 "answer"=課題提出

      ─── 変数4 ───
      フィールド名（変数名）: sys_files
      種類（タイプ）: ファイル（Files）
      ラベル: 添付画像（Phase4,5用）
      必須: オフ（任意）

  [ ] 設定パネルの「確認」または「Save」をクリック

  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  3-3. 質問分類器ブロックの追加
  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  ※「質問分類器」はユーザーの発言が「質問」なのか「課題の提出」なのかを
    AIが自動で判断して振り分けてくれるブロックです

  [ ] 「開始」ブロックの右端の「+」ボタンをクリック
      または、右側の「ブロック追加」パネルから「質問分類器」を検索して
      キャンバスにドラッグ
  [ ] 「開始」ブロックから「質問分類器」ブロックに矢印を繋ぐ
      （開始ブロックの右端の丸 → 質問分類器の左端の丸をドラッグ）
  [ ] 「質問分類器」ブロックをクリックして設定:
      - 入力変数: {{sys_query}} を選択
      - モデル: gpt-4o-mini または claude-haiku-4-5 を選択
        （モデル選択欄が出る。コスト低めのものがおすすめ）
      - 「クラスを追加」で2つのクラスを設定:

        クラス1の名前: 「質問・雑談」
        クラス1の説明: ユーザーが何か質問をしている、教えてほしいと言っている、
                      または雑談している。課題への回答ではない。

        クラス2の名前: 「課題の提出」
        クラス2の説明: ユーザーが課題に対して回答を提出しようとしている。
                      「〜しました」「〜だと思います」など答えを述べている。

  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  3-4. ルートA：質問・雑談用のLLMブロック
  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  [ ] キャンバスの空いている場所に「LLM」ブロックを追加
  [ ] 「質問分類器」の「クラス1（質問・雑談）」の出口から
      この「LLM」ブロックに矢印を繋ぐ
  [ ] 「LLM」ブロックをクリックして設定:
      名前（ブロックのラベル）: LLM_メンター
      モデル: gpt-4o-mini または claude-haiku-4-5

      【システムプロンプト】（以下をそのままコピーして貼り付け）:
      ─────────────────────────────────────────
      あなたは「Dify mini Camp」の親切なAIメンターです。
      Difyを学ぶユーザーのサポートをしています。

      【キャラクター設定】
      - 優しく丁寧に、でも要点は簡潔に説明する先輩エンジニア
      - 初心者でもわかるよう専門用語には必ず説明を添える
      - 困っているユーザーを励ましながらサポートする
      - 絵文字は控えめに使い、読みやすい文章を心がける

      【現在の状況】
      ユーザーの現在のフェーズ: Phase {{current_phase}}

      【Phase 1の学習内容】
      - 目標: Difyで「開始→LLM→回答」の3ブロックを繋いで動かすこと
      - キーワード: 開始ブロック、LLMブロック、回答ブロック、ノード、ワークフロー

      【対応方針】
      - 質問にはわかりやすく具体的な手順で答える
      - Difyの操作方法を聞かれたら「〇〇の画面で〇〇をクリック」と具体的に
      - わからないことは正直に伝え、公式ドキュメントを参照するよう促す
      - 回答は短すぎず長すぎず、200〜400字程度を目安にする
      ─────────────────────────────────────────

      【ユーザーメッセージ欄】:
      {{sys_query}}

  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  3-5. ルートB：課題提出用のテンプレートブロック
  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  ※テンプレートブロックは「複数の変数を組み合わせたテキスト」を作るブロックです
    ここでは「ユーザーの回答」と「現在のフェーズ」を1つのテキストにまとめます

  [ ] キャンバスに「テンプレート」ブロックを追加
  [ ] 「質問分類器」の「クラス2（課題の提出）」の出口から繋ぐ
  [ ] 「テンプレート」ブロックをクリックして設定:
      名前: テンプレート_採点準備

      テンプレート内容（以下をコピー）:
      ─────────────────────────────────────────
      【採点対象情報】
      現在のフェーズ: Phase {{current_phase}}
      ユーザーの回答: {{sys_query}}
      ─────────────────────────────────────────

      変数の設定:
      - current_phase → 開始ブロックの current_phase を選択
      - sys_query → 開始ブロックの sys_query を選択

  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  3-6. ルートB：採点用のLLMブロック
  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  [ ] キャンバスに別の「LLM」ブロックを追加
  [ ] 「テンプレート_採点準備」ブロックから繋ぐ
  [ ] 設定:
      名前: LLM_採点
      モデル: gpt-4o-mini または claude-haiku-4-5

      【システムプロンプト】:
      ─────────────────────────────────────────
      あなたはDify学習コースの採点AIです。
      ユーザーの回答を評価して、必ず以下のJSON形式「のみ」で回答してください。
      JSON以外の文字（説明・挨拶など）は一切含めないこと。

      【Phase 1 の採点基準】
      - 問題: Difyで最初に作る3ブロック構成を答えてもらう
      - 正解: 「開始（Start）」「LLM」「回答（Answer）」の3つが含まれていること
      - 採点: 3つのブロック名が概ね正しく答えられていれば合格（is_cleared: true）
      - 部分的に正しい場合: 不合格（is_cleared: false）としてヒントを出す

      【出力形式】（必ずこの形式を守ること！）
      {
        "is_cleared": true,
        "feedback_message": "正解です！〇〇を正しく理解していますね。",
        "next_action": "phase_cleared"
      }

      不合格の場合:
      {
        "is_cleared": false,
        "feedback_message": "もう少し！〇〇ブロックが足りません。ヒント:〜",
        "next_action": "try_again"
      }

■ よくあるつまずきポイントと解決法
================================================================

  Q: npx コマンドが「見つかりません」と出る
  A: Node.jsがインストールされていない。https://nodejs.org からインストール

  Q: git push でエラーが出る
  A: GitHubの認証が必要。Personal Access Token（PAT）を作成して使う
     GitHubの Settings → Developer settings → Personal access tokens → Tokens (classic)
     「Generate new token」→ 権限は「repo」にチェック → 生成されたトークンをパスワードとして使用

  Q: Difyのブロックが「変数集約器」という名前で見つからない
  A: バージョンによって名前が違う場合がある。「Merge」「Aggregator」「変数統合」などを探す

  Q: DifyのLLMが「モデルが設定されていない」と言う
  A: Difyの「設定」→「モデルプロバイダー」でOpenAIやAnthropicのAPIキーを設定する必要がある
     ※ DifyはAIモデルのAPIキーを別途用意する必要があります

  Q: .env.local を作ったのに環境変数が反映されない
  A: 開発サーバー（npm run dev）を再起動する

  Q: Vercelでデプロイしたらエラーになった
  A: Vercelのダッシュボードで「Deployment」→「Build Logs」を確認して Claude Code に相談
