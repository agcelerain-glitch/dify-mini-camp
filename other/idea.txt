Difyの設計は下記の通り


すべてのフェーズを1つにまとめる場合、「ユーザーが今どのフェーズにいるのか」と「単なる質問なのか、課題への回答なのか」をDify側が理解し、処理を分岐（ルーティング）させる仕組みが重要になります。

具体的なブロックの組み込み方と、直列・並列処理の仕組みを解説します。

1. 全フェーズを1つで処理する全体アーキテクチャ
Webアプリ（Next.js）側からDifyのAPIを叩く際、ユーザーの入力テキストだけでなく、「現在のフェーズ」や「画像」などの変数を渡すことで、Dify内部で処理を切り替えます。

開始ブロックの設定
開始ブロックには、以下の変数を定義しておきます。

sys_query (文字列): ユーザーの入力テキスト

sys_image (ファイル): アップロードされた画像（Phase 4, 5用）

current_phase (数値または文字列): Webアプリ側から渡される現在のフェーズ（例: "1", "2"）

interaction_type (文字列): "question" (壁打ち・質問) または "answer" (課題提出)

IF/ELSEブロックによる大分岐
開始の直後に巨大な交差点を作ります。ここでIF/ELSEブロックを使い、current_phaseの値に応じてPhase 1〜5の各専用ルートへ処理を流します。

2. 直列処理と並列処理の具体的なフロー構造
ブロックをどう繋ぐか、フェーズごとの具体例です。

【直列処理】 Phase 1〜2のシンプルな判定ルート
処理を一本道で順番に行う構成です。シンプルでデバッグが容易です。

開始: sys_query と current_phase = 1 を受け取る。

IF/ELSE: Phase 1のルートへ分岐。

質問分類器: ユーザーの入力が「雑談・質問」か「課題への回答」かをLLMに分類させる。

「雑談・質問」の場合 ➔ 通常の LLM (解説を行う) ➔ 回答

「課題への回答」の場合 ➔ 採点用の LLM へ進む。

LLM (採点用): 入力内容と正解を比較し、正誤判定とフィードバックの文章を生成する。

回答: 採点結果をWebアプリに返す。

【並列処理】 Phase 4〜5の高度な判定ルート
複数のブロックを同時に走らせ、後で結果を統合する構成です。応答速度の向上や、多角的な評価を行いたい場合に有効です。

開始: sys_query, sys_image, current_phase = 4 を受け取る。

IF/ELSE: Phase 4のルートへ分岐。

並列処理の開始: 画像判定とテキスト検索を同時に実行します。

ルートA: LLM (Vision対応): sys_image を読み込み、Difyの設定画面（スクショ）が要件を満たしているか判定する。

ルートB: 知識検索 (RAG): sys_query (ユーザーの補足説明など) を基に、公式ドキュメント等のナレッジから関連情報を検索する。

変数集約器 (または最終LLM): ルートAの「画像判定結果」と、ルートBの「検索した知識」を合流させ、最終的な評価フィードバックを生成する。

回答: 統合された結果をWebアプリに返す。

3. 各ブロックの具体的な使い所アイデア
リストアップしていただいたブロックのうち、Dify mini Campで特に活躍するものの役割を整理します。

テンプレート / 変数代入: LLMに渡すプロンプトを組み立てる際に使います。例えば「ユーザーの回答」と「模範解答」を一つのテキストに整形してから採点LLMに渡す際などに便利です。

コード実行 (Python/JS): LLMが出力したテキストから「正解」「不正解」というフラグだけを確実に抽出したい場合、簡単な正規表現コードを書いてデータを成形します。

ツール / HTTPリクエスト: 将来的な発展として、Dify側から直接Supabaseのデータベースを更新（クリアフラグを立てる等）したい場合に使用します（※今回はWebアプリ側で進捗管理を行うため、初期は不要です）。

ループ / リスト処理: もし「複数の課題をまとめて判定する」ような仕様になった場合、リスト化された回答を順番に採点するために使います。

4. Webアプリ連携のための重要なポイント
Difyの出力をそのままWebアプリの画面に表示するだけでは、「ユーザーがクリアしたかどうか」をシステムが判断できません。そのため、最終的な回答ブロックの出力は、単なる文章ではなくJSON形式にするのがベストプラクティスです。

回答ブロックが出力するJSONの例:

JSON
{
  "is_cleared": true,
  "feedback_message": "正解です！LLMブロックの役割を完璧に理解していますね。",
  "next_action": "go_to_phase2"
}
このように出力されるよう、各ルートの最後のLLMに「必ず指定のJSONフォーマットで出力すること」と指示（システムプロンプト）をしておきます。
